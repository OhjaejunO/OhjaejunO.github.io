1마이리얼트립 — 환불 규정 네비게이터

여행 플랫폼 · CS 자동화

문제

여행 상품 환불 규정은 카테고리·항공사·취소 시점·사유에 따라 갈라지고, CS 상담원과 고객 모두 "이 경우 얼마가 환불되는가"를 규정 원문에서 직접 찾아야 합니다. LLM에게 그냥 물으면 그럴듯하지만 틀린 답이 나올 수 있고, 환불액은 틀리면 안 되는 숫자입니다.

설계 판단

판정·계산은 100% 결정적 룰 엔진. LLM은 입력 변환(정규화)만.

같은 입력이면 언제나 같은 환불액이 나와야 신뢰할 수 있습니다. 규정 해석을 확률에 맡기지 않았습니다.

  • 헬프센터 원문 12개 문서를 규칙 JSON으로 구조화 — 전 규칙에 출처 링크·확인 일자 부착
  • 입력: 카테고리·항공사·취소 시점·사유 → 출력: 예상 환불액·수수료 내역·필요 증빙 + 근거 조항 링크
  • 공식 사이트 403 차단 → Zendesk 공개 API로 우회해 원문만 사용 (추측·요약본 배제)

검증

  • 경계값 검증 32건 통과 (취소 시점 경계·수수료 구간 경계 중심)
  • Codex 교차 리뷰로 로직 버그 3건 발견·수정 — 이종 AI 교차 감리를 검증 공정에 포함

2메디테라피 — 4개국 규제 온톨로지

화장품 · 글로벌 진출 검토

문제

화장품이 해외에 나가려면 성분과 마케팅 문구가 나라마다 다른 규제를 통과해야 합니다. 한·미·일·아세안 4개 권역의 규제를 사람이 매번 대조하는 것은 느리고, LLM이 "될 것 같다"고 말하는 것은 근거가 아닙니다.

설계 판단

출처 없으면 '미판정' — 모르는 것을 아는 척하지 않는 설계.

모든 판정에 법령 원문 출처가 붙습니다. 출처를 못 찾은 항목은 그럴듯한 추정 대신 '미판정'으로 명시합니다.

  • 입력: 전성분(INCI)·마케팅 문구 → 출력: 권역별 규제 리스크 판정 + 공식 조항 링크
  • 성분 규칙 56건 · 문구 규칙 26건 — 전부 법령 원문 출처 부착

검증

  • 실제 공개 제품 5종으로 판정 결과를 실물 대조

3두 플러그인의 공통 설계 원칙

판정은 규칙 · LLM은 보조

규정 판정이 비결정적이면 신뢰가 무너집니다. LLM은 정규화·플래그까지만 담당하고, 판정과 계산은 출처 추적 가능한 결정적 규칙이 수행합니다. 이 원칙은 본선 설계(AX 시딩 엔진)와 AI 콘텐츠 채널의 운영 규칙(이중 출처 교차 확인·출처 우선)으로 그대로 이어집니다.
