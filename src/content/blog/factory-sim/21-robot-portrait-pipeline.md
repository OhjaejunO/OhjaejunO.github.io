지난 편 말미에 경사 컨베이어로 돌아간다고 예고했는데, 한 편 더 밀렸다. HUD에 얼굴이 필요했기 때문이다.

이 게임의 대화 패널에는 플레이어에게 상황을 알려주는 AI 조수가 붙어 있다. 텍스트만 덜렁 있는 말풍선과, 화자의 얼굴이 있는 말풍선은 체감이 완전히 다르다. 그래서 포트레이트 칸을 만들기로 했는데 — 무엇을 넣을 것인가.

---

## 1. 왜 로봇인가

선택지는 셋이었다. 실사풍 이미지, 2D 일러스트, 아니면 3D 캐릭터.

실사와 일러스트는 빠르지만 **세계관에서 겉돈다.** 이 게임은 불시착한 행성에서 로봇들과 공장을 짓는 SF다. 마침 발표자료의 팀 프로필도 팀원별 로봇 6종으로 만들어 둔 참이었다 — 세계관이 이미 "로봇"으로 통일되어 있는데, 대화 패널에만 사람 얼굴이 뜨면 어색하다.

그래서 셋째 길로 갔다. **"우리 게임 안에 실재하는 3D 로봇"을 만들어서, 게임 카메라로 직접 찍는다.** 포트레이트가 정적 이미지가 아니라 씬 캡처가 되면 얻는 게 하나 더 있다 — 로봇이 idle 애니메이션으로 살아 움직이고, 나중에 대사에 맞춰 고개를 끄덕이거나 표정(이라기보단 발광부 점멸)을 바꾸는 확장이 **이미지 교체가 아니라 애니메이션 추가**로 가능해진다.

## 2. 파이프라인 — 이미지 한 장이 HUD에 뜨기까지

전체 흐름은 이렇다.

```
[GPT 이미지 생성 — 로봇 컨셉 아트 1장]
        ↓
[Meshy Image-to-3D — GLB (메시 + 텍스처 + idle 애니)]
        ↓
[UE5 임포트 — SkeletalMesh / Skeleton / 텍스처 / 애니]
        ↓
[AOJJ_PortraitCapture — 전용 캡처 액터 (조명·프레이밍·SceneCapture2D)]
        ↓
[RT_RobotPortrait — 512×512 RenderTarget, 매 프레임 갱신]
        ↓
[M_Portrait_UI — 알파 반전 UI 머티리얼]
        ↓
[WBP_DialogueBalloon / WBP_MainHUD — IMG_Portrait 칸]
```

컨셉은 GPT 이미지 생성으로 뽑았다. "우주 공장의 AI 조수 로봇" 톤으로 여러 장 굴려서 한 장을 골랐고, 그 이미지를 Meshy의 Image-to-3D에 넣으면 리깅된 GLB가 나온다. idle 애니메이션까지 붙여 주니, UE5에 임포트하면 바로 움직이는 스켈레탈 메시가 된다. 여기까지는 정말 반나절 작업이다.

핵심은 그다음의 **전용 캡처 액터** `AOJJ_PortraitCapture`다. 로봇 메시, 조명 2개, 스프링암, SceneCapture2D를 한 액터에 묶었다.

- **로봇만 찍는다** — `PRM_UseShowOnlyList` + `ShowOnlyActors(self)`. 배경도, 다른 액터도 캡처에 안 들어온다.
- **배경은 투명하다** — 캡처 소스를 `SCS_SceneColorHDR`로 두면 알파에 "역불투명도"(배경=1, 로봇=0)가 담긴다. 이걸 UI 머티리얼 `M_Portrait_UI`에서 `1-Alpha` 한 번만 반전해 로봇=불투명/배경=투명으로 만든다. 반전을 캡처 측과 UI 측 두 곳에 두면 언젠가 이중 반전으로 터지므로, **한 곳으로 단일화**했다.
- **환경광을 다 끈다** — ShowFlags에서 대기/안개/스카이라이팅/블룸/AO를 차단하고, 액터에 붙인 KeyLight(정면 위)와 FillLight(반대편 아래)로만 조명한다. 씬의 낮밤 사이클과 무관하게 포트레이트 톤이 일정해진다.
- **프레이밍은 자동이다** — 메시 바운드에서 전체 높이를 읽어 상반신 비율(0.42)만큼을 화면에 채우도록 스프링암 피벗과 카메라 거리를 계산한다. 나중에 로봇을 다른 메시로 갈아 끼워도 카메라를 다시 잡을 필요가 없다. 앵글은 정면에서 18° 튼 3/4 측면 — 증명사진보다 프로필 사진이 낫다.
- **스폰도 자동이다** — `UWorldSubsystem`이 화이트리스트 레벨에서 캡처 액터를 자동 스폰한다. 레벨 추가는 코드 수정이 아니라 Project Settings의 `UDeveloperSettings` 항목 편집이다. 스폰 위치는 월드 밖 Z=-5000 — 게임 씬과 완전히 격리된 지하 스튜디오다. (이 격리가 나중에 사고를 친다. 4장에서.)

위젯 쪽은 허무할 만큼 간단하다. Image Brush에 `M_Portrait_UI`를 할당하면 끝 — RT는 서브시스템이 알아서 갱신하고 있으니, UI 담당 팀원에게는 "머티리얼 붙이고 1:1 비율만 지켜 달라"는 인수인계 문서 한 장으로 넘어갔다.

여기까지가 첫날이다. PIE를 돌리니 말풍선 옆에서 로봇이 idle을 돌고 있었다. 파이프라인 완성 — 이라고 생각했다.

## 3. 삽질 1: 다음 날 로봇이 흰색 노이즈가 됐다

에디터를 재시작하고 열어 보니 **포트레이트가 흰색 바탕에 노이즈였다.** 어제는 분명 멀쩡했다. 머티리얼을 열어 보니 Texture Sample 노드가 ERROR를 뱉고 있었고, 참조 텍스처는 엔진 DefaultTexture로 떨어져 있었다.

범인은 **Meshy GLB를 임포트할 때 Interchange가 자동 생성한 머티리얼 인스턴스(`Material_1`)**였다. 이 자동 인스턴스가 텍스처 바인딩과 부모 머티리얼을 제대로 직렬화하지 못한다. 임포트 직후 메모리에 있을 때는 정상으로 보이는데, **에디터를 재시작하거나 다른 기기에서 로드하면** 바인딩이 풀려서 DefaultTexture로 떨어진다. 확인해 보니 로봇만이 아니라 같은 방식으로 임포트한 Man/Woman 캐릭터도 전부 같은 결함을 안고 있었다.

사실 Interchange의 자동 머티리얼에는 전과가 있다. 이전 팀 프로젝트에서 같은 에셋이 데스크탑에서는 멀쩡하고 노트북에서만 흰색으로 나오는 문제를 추적했을 때도, 원인은 FBX 임포터의 fallback 머티리얼이 플러그인 가상 경로에 걸려 있던 것이었다. 그때 교훈이 "임포트가 만들어 준 머티리얼은 환경이 바뀌면 신뢰할 수 없다"였는데 — 이번엔 환경 차이도 아니고 **재로드만으로** 깨졌다. 두 번째로 같은 종류의 칼에 베인 셈이다.

그래서 이번엔 우회가 아니라 절연을 택했다.

1. **자동 생성 머티리얼을 폐기한다** — `Material_1` 삭제.
2. **수동 베이스 머티리얼 `M_Robot`을 직접 만든다** — 인스턴스를 경유하지 않는 평범한 UMaterial에 baseColor/metallic-roughness/normal/emissive 4채널 텍스처를 직접 연결.
3. **GLB를 재임포트하며 텍스처만 새로 받는다** — 메시/스켈레톤/idle 애니는 에셋 이름을 유지해서, C++의 `ConstructorHelpers` 경로가 한 줄도 안 바뀌게.
4. 메시의 머티리얼 슬롯을 `M_Robot`으로 교체.

에디터를 재시작해도, 다른 기기에서 받아도 ERROR가 없는 걸 확인하고 나서, 이걸 프로젝트 임포트 규약으로 못 박았다 — **"AI 생성 GLB의 자동 머티리얼은 쓰지 않는다. 임포트 시 머티리얼 자동 생성에 의존하지 말고, 수동 베이스 머티리얼을 만들어 텍스처를 직접 연결한다."** 로봇 하나면 사고지만, 앞으로 Meshy 에셋이 캐릭터마다 들어올 프로젝트에서는 규약이 있어야 파이프라인이다.

## 4. 삽질 2: 이번엔 포트레이트가 흐릿하다

머티리얼을 고치고 나니 다음 증상이 왔다. **첫 PIE에서 포트레이트가 잠깐 깨진 회색으로 떴다가, 어떤 날은 계속 흐릿한 저해상도로 남았다.** 이 문제는 한 번에 안 잡히고 세 번에 걸쳐 원인이 벗겨졌다.

### 4-1. 고정 지연 0.3초 — 얕은 수정

첫 진단: 캡처가 `BeginPlay`부터 매 프레임 도는데, 에디터 첫 PIE 시점엔 `M_Robot`의 셰이더가 아직 컴파일 중이라 로봇이 디폴트 머티리얼인 채로 RT에 찍힌다. 그래서 `bCaptureEveryFrame=false`로 시작하고 0.3초 타이머 뒤에 캡처를 켜는 워밍업을 넣었다.

대부분의 경우 통했다. 하지만 "대부분"이라는 게 문제다 — DDC(셰이더 캐시)가 콜드한 머신에서는 컴파일이 셰이더당 ~0.42초, 총 수 초씩 걸린다. 0.3초는 그냥 **운이 좋길 비는 숫자**였다.

### 4-2. 셰이더 컴파일 폴링 — 지연이 아니라 완료를 기다린다

고정 지연을 버리고, 실제 완료 신호를 폴링하는 것으로 바꿨다.

```cpp
#if WITH_EDITOR
    if (GShaderCompilingManager && GShaderCompilingManager->IsCompiling())
    {
        bWaiting = true;   // 0.15s 간격 재폴링, 최대 15s 안전망
    }
#endif
```

`WITH_EDITOR` 가드를 친 이유: 패키징 빌드는 셰이더가 쿡되어 있어 이 문제 자체가 없다. 에디터 전용 대기를 런타임에 남길 이유가 없다.

이걸로 회색 로봇은 사라졌다. 그런데 —

### 4-3. 그래도 흐릿하다 — 진범은 텍스처 스트리밍

셰이더가 다 컴파일된 뒤에 찍었는데도 포트레이트가 흐릿한 케이스가 남았다. 로그를 까 보니 캡처 시점에 로봇 텍스처의 **mip이 12단계 중 7단계까지만 올라와 있었다.** 셰이더는 멀쩡했고, 텍스처가 저해상도 mip인 채로 찍힌 거다.

왜 안 올라왔는가 — 2장에서 자랑했던 **Z=-5000 격리 배치가 부메랑으로 돌아왔다.** UE5의 텍스처 스트리밍은 화면 커버리지 기반이다. 메인 카메라에 보이지도 않는 지하 스튜디오의 로봇은 스트리머 입장에서 "화면을 거의 차지하지 않는 물체"라서, 고해상도 mip을 올려 줄 이유가 없다. SceneCapture가 그 로봇을 512×512로 크게 찍고 있다는 사정은 스트리머가 모른다.

그래서 캡처 액터가 직접 개입한다. BeginPlay에서 로봇 머티리얼이 쓰는 텍스처를 전부 수집해 **강제 resident를 걸고**, 워밍업 폴링 조건에 "전체 mip 스트림인 완료"를 추가했다.

```cpp
// BeginPlay — 렌더 여부와 무관하게 전체 밉 스트림인 요청
RobotTexturesPrevForceResident.Add(Tex2D->bForceMiplevelsToBeResident); // 원래 값 저장
Tex2D->bForceMiplevelsToBeResident = true;

// 워밍업 폴링 — 셰이더(에디터) AND 텍스처 full-resident(공통) 둘 다 기다린다
if (Tex2D->GetNumResidentMips() < Tex2D->GetNumMips())
{
    bWaiting = true;
}
```

이쪽은 `WITH_EDITOR` 가드가 **없다.** 텍스처 스트리밍은 패키징 빌드에서도 똑같이 도는 런타임 메커니즘이라, 에디터 전용으로 좁히면 출시 빌드에서 흐릿한 첫 캡처가 재발한다.

디테일 하나 — 코드 리뷰에서 Major로 잡힌 게 force 플래그의 수명이었다. `bForceMiplevelsToBeResident`는 에셋 공유 상태라, 액터가 사라진 뒤에도 true로 남으면 그 텍스처는 영원히 풀밉으로 메모리를 문다. 그래서 `EndPlay`에서 **무조건 false가 아니라 저장해 둔 원래 값으로 복원**한다 — 다른 시스템이 걸어 둔 force를 우리가 지우면 안 되니까.

세 번의 진화를 요약하면:

| 단계 | 기다리는 것 | 방식 | 한계 |
|------|------------|------|------|
| A-1 | (추정) 셰이더 | 고정 0.3s 지연 | DDC 콜드면 실패 |
| A-2 | 셰이더 컴파일 | `IsCompiling()` 폴링 | 텍스처는 못 봄 |
| A-3 | 셰이더 + 텍스처 mip | force-resident + `GetNumResidentMips()` 폴링 | — |

첫 PIE부터 풀해상도 포트레이트가 뜨는 걸 확인했고, 15초 타임아웃 경고도 없었다.

## 5. 정리 — AI 에셋은 규약이, RT 캡처는 시점이 전부다

로봇 포트레이트에서 한 것 —

- 세계관 통일을 위해 실사/일러스트 대신 **인게임 3D 로봇 실시간 캡처**로 확정 (GPT 컨셉 → Meshy Image-to-3D → UE5)
- 전용 캡처 액터: ShowOnly 셀프 캡처 + SceneColorHDR 알파 + UI 측 단일 반전 + 바운드 자동 프레이밍 + 서브시스템 자동 스폰
- Interchange 자동 머티리얼의 직렬화 결함 → **수동 베이스 머티리얼 직결**로 절연, 임포트 규약으로 격상
- 첫 프레임 글리치 → 고정 지연 → 셰이더 폴링 → **force-resident + mip 폴링**까지 세 단계 진화

교훈은 두 줄이다.

**AI 생성 에셋은 임포트 규약을 정해야 파이프라인이 된다.** 생성은 반나절이지만, 자동 임포트가 만들어 준 중간 산물(머티리얼)을 그대로 믿으면 "내 기기에서 어제는 됐는데"류의 시한폭탄이 남는다. 한 번은 사고고, 규약을 만들면 그때부터 파이프라인이다.

**RT 캡처는 "찍는 시점"의 리소스 상태를 보장해야 한다.** 셰이더 컴파일과 텍스처 스트리밍은 완료 시점이 다르고, 둘 다 캡처는 기다려 주지 않는다. 고정 지연은 추측이고, 폴링은 확인이다 — 그리고 격리 배치처럼 렌더링에서 공짜인 트릭이 스트리밍에서는 공짜가 아니라는 것까지가 이번 편의 수업료였다.

로봇은 이제 말풍선 옆에서 첫 프레임부터 선명하게 idle을 돌고 있다. 다음 편은 이번에야말로 밀린 경사 컨베이어·메시 개편이다.
