19편이 게임의 첫 화면이었다면, 이번엔 마지막 화면이다. 이 게임의 최종 목표는 **통신탑**이다. 불시착한 행성에서 공장을 굴려 자원을 모으고, 마지막에 통신탑을 세워 구조 신호를 쏘아 올린다. 그 마지막 배치 버튼을 누르는 순간 — 무엇을 보여줄 것인가.

## 1. 어떤 컷은 인게임에 존재하지 않는다

엔딩 콘티를 짜 보니 컷이 두 부류로 갈렸다.

**컷1 — 내가 지은 통신탑과 공장.** 이건 반드시 인게임이어야 한다. 플레이어마다 공장 모양이 다르다. 컨베이어를 어디로 뽑았는지, 파운데이션을 몇 층 쌓았는지 전부 다른데, 프리렌더 영상 속 남의 공장이 나오면 감동이 없다. "저거 내가 지은 거다"가 이 컷의 전부다.

**컷6~8 — 행성 곳곳에서 신호를 받은 다른 생존자들.** 이건 인게임에 존재하지 않는 장면이다. 다른 생존자 캐릭터도, 그들의 캠프도, 애니메이션도 게임에 없다. 이걸 인게임으로 만들려면 엔딩 한 번을 위해 에셋과 연출을 통째로 새로 만들어야 한다. 반대로 AI 영상 생성에게는 "행성 어딘가의 생존자가 하늘을 올려다본다"는 그냥 프롬프트 한 줄이다.

그래서 하이브리드로 확정했다 — **컷1은 인게임 카메라, 나머지는 AI 생성 영상을 UMG Media 위젯으로 재생.** 시퀀서 없이 "내 공장을 비추는 개인화 연출"과 "게임에 없는 장면의 고품질 영상"을 둘 다 가져가는 구조다.

말은 깔끔한데, 이 글의 나머지는 전부 그 두 컷 **사이의 이음새**에서 벌어진 삽질이다.

## 2. C++ 시퀀스 — 트리거에서 복귀까지

전체 흐름부터. 시퀀서를 안 쓰기로 했으니 단계 전환은 전부 C++ 상태 머신이다.

```
[통신탑 배치 함수 끝 — 엔딩 조건 판정 + 플래그 캡처]
        ↓
[컷1: 카메라 스폰 — 탑 Bounds 로우앵글, smoothstep 푸시인 4초]
        ↓
[페이드 아웃 (Slate 오버레이 — 3장에서)]
        ↓
[컷2: AI 영상 위젯 (OnMediaOpened 게이트 — 4장에서)]
        ↓
[bGameCleared 세이브 → 스타트 화면 복귀]
```

**트리거는 배치 함수의 끝이다.** 엔딩 조건(통신탑 완성)이 바뀌는 유일한 지점이 배치 처리이므로, Tick으로 폴링할 이유가 없다. 판정 결과는 플래그로 캡처해서 같은 프레임에 배치가 여러 번 처리돼도 시네마틱은 한 번만 시작한다. `bGameCleared`는 트리거 직후 세이브에 기록 — 시네마틱 도중 게임을 꺼도 클리어가 유실되지 않고, 재로드 시 엔딩이 또 발동하지도 않는다.

**컷1 카메라는 하드코딩이 아니라 탑의 Bounds에서 산출한다.** 플레이어마다 공장 규모가 다르니 고정 좌표는 애초에 불가능하다. Bounds 바깥 낮은 높이에서 올려다보는 로우앵글로 규모감을 만들고, 푸시인은 4초 smoothstep 보간이다.

<video autoplay muted loop playsinline src="/videos/projects/factory-space/ending-beam.mp4"></video>

```cpp
// 푸시인: 선형 보간의 기계적 등속감 제거
const float S = FMath::SmoothStep(0.f, 1.f, Alpha);   // Alpha: 0→1 / 4초
Camera->SetActorLocation(FMath::Lerp(StartLoc, EndLoc, S));
```

디테일 하나 — **LookAt은 Bounds 정중앙(50%)이 아니라 25% 지점**을 본다. 중앙을 보면 화면 한가운데가 비어 보이고, 25% 지점을 보면 전경에 구조물이 걸리면서 화면 밀도가 산다. 몇 번 찍어 보고 나온 경험값이다.

그리고 설계 원칙 하나. 이 시퀀스는 카메라 블렌드·페이드·미디어 Open·재생 완료까지 **비동기 단계의 연쇄**라서, 어느 한 단계의 콜백이 유실되면 게임이 영원히 입력 잠금 상태로 남는다. 19편 인트로에서 soft-lock 세 개를 잡으며 배운 그 교훈 그대로 — **모든 비동기 단계는 "정상 신호 OR 폴백 타이머" 중 먼저 오는 쪽으로 반드시 전진하고, 모든 비정상 경로는 `FinishEndingSequence()` 하나로 수렴한다.** 영상 파일이 없어도, 디코더가 죽어도, 최종적으로 스타트 화면 복귀는 보장된다.

## 3. 페이드 삽질기 — 카메라 페이드는 UMG를 못 덮는다

컷1에서 컷2로 넘어가려면 화면을 검게 덮었다가 열어야 한다. 페이드 하나가 뭐 어렵겠나 싶었는데, 이번 작업 최대의 삽질이 여기서 나왔다.

**1차 — UMG Widget Animation.** 검은 이미지를 가진 위젯에 페이드 애니메이션을 만들어 재생. 세 번을 다르게 시도했는데 세 번 다 실패했다. 애니메이션 바인딩이 풀리거나, 재생 타이밍이 밀리거나, 아예 트랙이 안 먹었다.

**2차 — C++ RenderOpacity 직접 제어.** 위젯 애니를 포기하고 C++ 타이머에서 `SetRenderOpacity`로 알파를 보간했다. 페이드 자체는 되는데 치명적인 문제 — 위젯이 뜨는 순간이 **투명 상태에서 딱 나타난다.** 알파를 0에서 시작해도, 위젯이 뷰포트에 추가되는 프레임과 첫 Opacity 적용 프레임 사이의 틈이 보였다.

**3차 — `StartCameraFade`.** "그래, 엔진에 페이드 API가 있는데 왜 만들고 있지." `APlayerCameraManager::StartCameraFade`를 걸었다. 씬은 완벽하게 검게 덮였다. 그런데 **AI 영상 위젯이 페이드 위에 그대로 떠 있었다.**

원인은 파라미터가 아니라 **레이어 구조**다. 카메라 페이드는 씬(3D 렌더) 위에 페이드 색을 합성하는데, UMG(`AddToViewport`)는 그보다 위의 Slate 레이어에 그려진다. `bHoldWhenFinished`를 아무리 붙잡아도 UMG는 안 덮인다. UE5.7에서 직접 확인했다. "영상 위젯이 떠 있는 상태에서 화면 전체 페이드"라는 이 연출의 요구사항과 정면으로 충돌하는 구조적 한계였다.

**최종 해법 — 검은 `SImage`를 Slate 레이어에 직접 부착.** UMG를 덮으려면 UMG보다 높은 곳에 있어야 한다. `UGameViewportClient::AddViewportWidgetContent`로 뷰포트에 직접 넣으면 레이어 번호를 지정할 수 있다.

```cpp
SAssignNew(FadeOverlay, SImage)
    .ColorAndOpacity(FLinearColor(0, 0, 0, 0))      // 알파 0에서 시작
    .Visibility(EVisibility::HitTestInvisible);      // 입력 통과 — 없으면 UI가 전부 죽는다

if (UGameViewportClient* VC = GetWorld()->GetGameViewport())
{
    VC->AddViewportWidgetContent(
        SNew(SWeakWidget).PossiblyNullContent(FadeOverlay.ToSharedRef()),
        /*ZOrder=*/300);                             // UMG(ZOrder 200 = Slate 210) 위
}
```

여기서 **레이어 300의 근거**가 중요하다. 영상 위젯은 `AddToViewport(ZOrder=200)`으로 띄우는데, UMG의 ZOrder는 Slate 레이어로 매핑될 때 **+10 오프셋이 붙어 실제로는 210**이 된다. 그래서 300이면 확실히 위다. 참고로 "UMG 쪽 ZOrder를 올려서 해결"하는 방향은 갈 길이 아니다 — 페이드는 '모든 UI 위'여야 하므로 UI마다 ZOrder 경쟁을 시작하면 끝이 없다. 페이드만 레이어 300 고정이 단순하다.

계약이 두 개 따라온다. `HitTestInvisible`이 없으면 오버레이가 클릭을 삼켜 페이드 중 입력이 전부 죽고, `EndPlay`에서 `RemoveViewportWidgetContent`로 정리하지 않으면 레벨 전환 후에도 오버레이가 뷰포트에 남는다.

## 4. 잔상과의 싸움 — 신호는 첫 프레임보다 빠르다

페이드를 뚫고 나니 다음 적은 영상 첫 프레임이었다. 컷2 위젯이 열리는 순간, **이전에 재생했던 영상(인트로 시네마틱)의 마지막 프레임이 한 박자 먼저 화면에 떴다.**

원인은 `MediaPlayer`의 Open이 **비동기**라는 것. Media Texture에는 이전 재생의 마지막 프레임이 남아 있고, `Open Source` 후 로딩이 끝나기 전에 위젯을 보이게 하면 그 잔상이 그대로 노출된다.

해법은 게이트다 — **위젯을 Render Opacity 0으로 띄워 두고, `OnMediaOpened` 신호가 오면 그때 보이게 한다.** 신호가 안 오는 실패 경로(파일 누락, 디코더 에러)를 위해 2초 폴백 타이머를 함께 걸고, 신호 OR 타이머 중 먼저 오는 쪽이 게이트를 연다. 어느 쪽이 열었는지 알 수 있게 로그를 갈랐다.

```
[SIGNAL]   OnMediaOpened → 게이트 오픈      ← 정상 경로
[FALLBACK] 2.0s 타이머 → 게이트 강제 오픈    ← 신호 유실 경로
```

그런데 게이트를 달고도 잔상이 남았다. 로그는 매번 `[SIGNAL]` — 신호는 정상적으로 오고 있었다. 그래서 알게 된 것: **`OnMediaOpened`는 "파일이 열렸다"는 뜻이지 "첫 프레임이 디코딩되어 텍스처에 올라왔다"는 뜻이 아니다.** 신호가 첫 프레임 디코딩보다 빨리 도착하니, 신호 직후 바로 열면 여전히 잔상 또는 검은 프레임 한두 장이 보인다.

종결은 싱겁게 — **신호 후 +0.2초 지연.** 첫 프레임 디코딩 시간을 벌어 주는 경험값이다. `OnMediaOpened → 0.2s Delay → SetRenderOpacity(1)`. 여기에 Media Texture의 **Auto Clear**를 켜서 잔상의 근원(닫힌 소스의 마지막 프레임)도 함께 줄였다. Auto Clear만으로는 안 되는 게, Open 비동기는 그대로라 잔상이 "검은 프레임 노출"로 바뀔 뿐이다. 게이트와 Auto Clear는 세트다.

## 5. AI 영상 3클립 — 소리는 귀 말고 RMS로

마지막 남은 건 영상 자체. 컷2 이후의 엔딩 영상은 Seedance로 생성했는데, **한 번에 15초까지밖에 못 뽑는다.** 엔딩 분량이 그보다 길어서 3클립으로 나눠 생성하고 ffmpeg concat으로 이었다.

```bash
ffmpeg -f concat -safe 0 -i clips.txt -c copy ending_full.mp4
```

이어 붙인 영상을 재생해 보니 **클립 경계에서 음악이 뚝 끊겼다 다시 붙었다.** 문제는 "어디가 얼마나 비었는지"를 귀로는 특정할 수 없다는 것. 끊긴 건 알겠는데 클립2 끝이 문제인지 클립3 앞이 문제인지, 0.5초인지 5초인지 감이 안 왔다.

그래서 귀 대신 수치로 갔다 — **ffmpeg로 각 클립의 오디오 RMS 프로파일을 뽑아 시간축으로 비교했다.** 결과는 명확했다. **클립3의 첫 4.5초가 사실상 무음**(RMS 바닥)이었다. 클립1·2는 첫 프레임부터 음악이 실려 있는데 클립3만 조용히 시작했다가 4.5초 뒤에 음악이 들어오니, concat 경계에서 음악이 끊겼다 살아나는 것처럼 들린 거다.

원인을 알면 수정은 프롬프트 한 줄이다. 클립3을 **"음악이 첫 프레임부터 시작"을 명시**해서 재생성했고, 경계 끊김은 사라졌다.

돌이켜보면 2장~5장이 전부 같은 패턴이다. 페이드가 안 되는 이유는 눈으로 안 보였고(레이어 구조), 잔상의 원인은 로그를 가르기 전엔 안 보였고([SIGNAL]인데 잔상), 오디오 공백은 귀로 특정이 안 됐다(RMS로 4.5초). **감각으로 안 잡히면 구조와 수치로 내려가라** — 이 시리즈에서 몇 번째 반복하는 교훈인지 모르겠다.

## 정리 — 이음새가 연출이다

통신탑 엔딩에서 한 것 —

- 인게임에 존재하지 않는 컷(다른 생존자들)과 존재해야만 하는 컷(내 공장)을 갈라 **하이브리드 확정**
- 배치 함수 끝 트리거 → **Bounds 로우앵글 + LookAt 25% + smoothstep 푸시인 4초** → 페이드 → 영상 → 복귀, 모든 비정상 경로는 `FinishEndingSequence` 수렴
- UMG 애니 3연속 실패 → RenderOpacity 이관 → 카메라 페이드의 구조적 한계 확인 → **SImage 오버레이 레이어 300** (UMG ZOrder 200 = Slate 210 위)
- Media 잔상 → **OnMediaOpened 게이트 + 2s 폴백 + 신호 후 0.2s 지연** + Auto Clear
- Seedance 15초 한계 → 3클립 concat, 경계 끊김을 **RMS 프로파일**로 진단(클립3 첫 4.5초 무음) → 재생성

교훈을 세 줄로 줄이면 — **UMG 위 페이드는 카메라가 아니라 오버레이로. Media는 표시가 아니라 신호 게이트로. 소리는 귀가 아니라 RMS로.** 셋 다 "되겠지"가 아니라 구조를 확인하고 수치를 재고 나서야 풀렸다.

통신탑이 섰고, 신호가 나갔고, 엔딩이 나온다. 다음 편은 밀려 있던 경사 컨베이어·메시 개편으로 돌아간다.
